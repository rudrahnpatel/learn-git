# learn-git

A static web app that teaches git, from the first commit up to bisect and force-with-lease, as a daily game. A winding path of three-minute lessons (one exercise per screen, instant feedback), challenge nodes where you type real git commands into a simulated repository, and a git-flavoured reward layer to bring you back tomorrow: a streak drawn as your own commit line, daily quests, cherries to cherry-pick, release tags to ship, stashes that save a missed day, and achievements. Twig, a paper-cut sprout, cheers you on. The look follows a SuperHi-style "paper-cut classroom wall": light canvas, flat candy-coloured shapes, one electric violet for every action, with a matching dark mode (follows the system, or pick Light / Dark in the top bar).

It is plain static files: ES modules, one CSS file and two vendored fonts (Inter and Martian Mono, SIL OFL, in `fonts/`). There is no build step, no npm and no CDN, so it works offline and can be served from any static file server at any path (all URLs are relative). The one exception is optional: Google sign-in and cross-device progress sync (Supabase) load `supabase-js` from a CDN, and only for someone who signs in. With `js/cloud/config.js` left empty (the default) the app is local-only and every account feature hides itself. Setup: [`supabase/README.md`](supabase/README.md).

```sh
python3 -m http.server 8801 --directory .   # then open http://localhost:8801/
```

## What's inside

- **36 levels in 7 chapters**: Basics, Branching & merging, Rewriting history, Undoing things, Stash & workflow, Remotes, and Detective work. Every level has a plain-language concept, a goal, three hints that reveal one at a time, and a debrief.
- **Formats**:
  - puzzles: reach a goal state. Stars come from moves versus par, where a move is a command that changed the repo (inspecting is free).
  - rescue missions: wrong branch, `reset --hard` accident, leaked secret, bad merge, detached HEAD.
  - conflict surgeon: resolve hunk by hunk.
  - bisect hunt: a chapter level, plus a random replayable arcade mode.
  - speed round: 90 seconds of "which command does this?".
  - sandbox: saved in localStorage.
- **Graph-shape goals** show a mini "target" graph, generated by running the level's own solution.

cd tools/chest3d && npm install && npm run render   # writes icons/chest/*.webp

## The engine in one paragraph

`new Repo()` holds plain-JSON state in `repo.s`: a commit pool (`id, parents, msg, tree {path: content}, author`), branches, tags, HEAD (attached or detached), index, working tree, conflicts, stash, per-ref reflogs, an in-progress sequencer for rebase, cherry-pick and revert, a bisect session, and a fake `origin` with its own branches plus `origin/*` tracking refs. `repo.run('git merge feature')` parses the line (quotes, `&&`, `;`, `>`, `>>`) and returns `{lines, ok, events}`. Merges are real three-way merges, line by line in diff3 style, and they write conflict markers. Commit ids are 7 hex characters hashed from parents, message, tree and a counter, so every level is reproducible. A command that throws leaves the state exactly as it was.

## Adding a level

Add an object to `LEVELS` in `js/levels.js`, inside the chapter where it belongs:

```js
{
  id: 'my-level', chapter: 'undoing', kind: 'puzzle',     // puzzle | rescue | conflict | bisect
  title: 'Short title',
  concept: 'One plain paragraph (HTML allowed: <code>, <b>).',
  goal: 'What the player must achieve.',
  hints: ['gentle', 'stronger', 'nearly the answer'],
  debrief: 'What they learned and where it shows up in real life.',
  setup(r) {                                  // build the starting repo
    r.setupCommit('Initial commit', { 'a.txt': 'hello' });  // writes, stages everything, commits
    r.sh('git switch -c feature');            // run any command (throws if it fails)
    r.setupFiles({ 'a.txt': 'edited' });      // uncommitted changes
    // r.setupRemote(); r.teammatePush('main', 'msg', { file: 'x' }); r.s.bugMarker = 'BUG';
  },
  check: (r) => [                             // every [label, ok] must be true to win
    ['a.txt is committed', r.tree(r.headId())['a.txt'] === 'edited\n'],
  ],
  solution: ['git commit -am "Edit a"'],      // strings, or { todo: [['pick', 0], ['fixup', 1]] } for rebase -i
  // par: 3,          // defaults to solution.length
  // target: true,    // show the mini target graph
  // chips: ['git status', 'git commit -am ""'],
}
```

Then run `node tests/levels.test.mjs`. It fails if the goal is already met at the start, if any solution step errors (unless it stops for a conflict), if a check is unmet at the end, or if the solution goes over par.

## Limits (by design)

Remotes are simulated in-process (`origin` plus named remotes such as `upstream`, no network); no octopus merges, `bisect skip`, submodules, worktrees or hooks; `rebase -i` supports pick, reword, squash, fixup and drop, but not `edit` or `exec`. Rename detection is not modelled (a rename shows up as a delete plus an add). There is no editor, so commands that would open one either take `-m` or reuse the default message.
